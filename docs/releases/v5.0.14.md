# HLS Downloader v5.0.14

普通文件接管要能看见确认窗和完成窗：点击立刻弹出确认，下完弹出完成；功能界面保持原生、简洁、够用。媒体嗅探、媒体下载、投屏/TVBox 推送在 native-shell 空闲路径上也要能用。

具体变化：

- 浏览器扩展冷启动优先拉 `HLSNativeShell.exe`，不再先开 WebView2；`CREATE_NO_WINDOW` 不会再把确认/完成窗藏掉
- native-shell 还没 boot 时，offer 进入 `native-shell-pending`，boot 后立刻画出预创建的「浏览器下载」窗，不再落到没有界面的 `ui-fallback`
- 确认窗可改文件名和保存目录；点取消或关窗会 reject，浏览器下载不会一直停着
- 完成窗置顶，带路径/大小/打开/打开目录；主列表补上「打开」；打开安装包不再被 409 挡住
- 投屏 / TVBox 推送不再因为桌面 WebView 没开而 409；请求先排队，再拉起 `HLSDownloader.exe --settings` 打开设备选择窗
- 扩展快捷键 Ctrl+Shift+Y（嗅探当前页面）会打开当前标签的媒体面板
- 媒体嗅探更准：JSON playurl / 海报脚本不会再进 overlay；观看页 URL 不会当成正在播的文件；MSE 里精确匹配的 MP4 可以下载，同目录预览不会误绑
- 浏览器确认的 HLS/DASH 按 overlay 的 `resource_kind` 建任务，`.m3u` / `mpegurl` MIME 不再被当成普通文件
- DASH 直播结束合并带上已录制分片时间轴；投屏 `.ts` 使用 `video/mp2t`，HLS 用 LIVE 而不是 BUFFERED
- 设置/嗅探/投屏：空闲时拉起桌面 WebView；Ctrl+Shift+Y 无播放也列出页面资源；会话重启不再重放旧投屏；旧 `push_to_tv` 走设备选择窗
- 托盘退出会 POST `/desktop/native-shell/shutdown`，不再留下幽灵 ready；下一击在 Windows 上强制再拉 `HLSNativeShell.exe`，而不是永远停在「请在桌面确认」
- 多连接 GET 的 206 必须带匹配的 Content-Range，缺头或起点不对会按 Range 不支持退回单连接；明文 HTTP 的 Host 不再带默认端口，相对 Location 按当前目录拼接
- `--settings` 在 native-shell 已退出时自己建托盘；确认窗 accept/reject 失败会留在窗上显示错误；overlay / 弹窗的投屏、TVBox 按钮 busy 状态能跨 render 存活并等到设备选择结束
- 居民 HTTP 引擎在排队下一趟 GET 前会把 `native-engine.progress.json` 写成 `starting`，暂停/完成后的旧 terminal 状态不会再被当成新任务立刻退出（避免未下完的文件被标成完成）
- 明文 HTTP 遇到 `Transfer-Encoding: chunked` 会失败并回退 Python，而不是把 chunk 头写进文件；完成事件会把主列表行标成已完成；列表删除失败不再先把行拿掉
