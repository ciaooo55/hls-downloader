## 与成熟实现的对照

这次对照了 ABDM 浏览器集成公开源码、yt-dlp 的公开下载器/清单模型，以及 IDM 官方公开的集成说明。结论按“代码或官方文档明确写出的行为”记录：

| 能力 | ABDM / IDM 的公开证据 | HLS Downloader 当前实现 |
| --- | --- | --- |
| 普通下载接管 | ABDM 用 `webRequest` 记录请求链，在响应头确认附件后接管；IDM 集成模块负责在浏览器下载开始时转交桌面端 | Chromium 使用响应头预判 + `downloads.onCreated` 双路径，Firefox 使用可阻塞响应路径；暂停、失败恢复和重定向链均有真实 smoke |
| 媒体识别 | ABDM 按 `media` 响应、XHR 的 `.m3u8` 和逐标签页媒体注册表处理；IDM 官方只公开“监视链接并显示 Download This Video”行为，未公开实现 | 在同一请求链之上增加媒体元素 `currentSrc`、fetch/XHR、Performance、iframe/Shadow DOM 与 MSE `SourceBuffer` 证据；多 MSE 无归属证据时故意不猜 |
| HLS/DASH 元数据 | ABDM 解析 HLS master/variant，并拒绝加密清单；yt-dlp 原生 downloader 维护分片、重试和清单刷新，并可回退 FFmpeg | HLS/LL-HLS/DASH 原生解析、分片检查点、独立音轨/字幕、签名上下文和 FFmpeg 收尾；复杂 DASH 多 Period 仍保留兼容回退边界 |
| 识别速度与页面开销 | ABDM 的后台请求监听较轻，但公开实现不覆盖 MSE 字节归属；IDM 为闭源原生网络栈，无法从公开源码逐行验证 | 资源缓存、请求链、Blob/MSE 归属都有上限，MSE hook 仅在创建 `SourceBuffer` 后安装；Firefox/Edge 真实页面 smoke 无浏览器错误 |

对照结果没有发现应当无条件复制的“更稳定”算法：ABDM 的宽松自动接管更容易覆盖没有明确点击意图的下载，但也更容易接到隐藏 iframe/预加载；本项目保留“成功响应链 + 播放器/点击证据”的边界，以避免此前出现的页面控制器、广告和错误 frame 被当成目标视频。对于确实没有 `DownloadItem`、没有成功响应链、或 DRM/EME 的资源，任何扩展都不能凭空制造可重放下载地址。

## 明确的边界（不是待修 bug）

- DRM/EME、SAMPLE-AES 和没有授权的站点验证不会被绕过。
- 同一 frame 多个 MSE 播放器没有 HTTP/SourceBuffer 归属证据时，会保守地要求用户选择，不会把广告误投到主视频。
- 失效的一次性签名不能凭空恢复；扩展只能使用当前浏览器成功请求链，或在桌面重试失败后保留/恢复浏览器原下载。
- DASH 多 Period 发生编解码/初始化切换时仍可能退回 yt-dlp；原生断点能力以可验证的播放计划为前提。
- 浏览器商店插件的静默升级由 Chrome Web Store/Firefox AMO 承担；解压加载的 Chrome 包不能伪造商店自动更新。
