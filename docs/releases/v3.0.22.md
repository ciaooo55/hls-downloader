# HLS Downloader v3.0.22

本版本把此前反复出现的“浏览器能下、桌面端失败”“直播 0 秒/误暂停”“投屏只会重新下载远程链接”等问题收敛到可验证的处理链：

- 短效 `s/e/_t` 文件链接在尚未到生效时间时进入可取消的等待状态；浏览器来源的签名 403、404/410 会在有真实请求上下文时进行一次浏览器兼容回退，普通 404 不会盲目重试。
- 浏览器接管严格绑定成功响应链、可信点击意图和实际下载项；Chromium 暂停后的瞬时 `interrupted` 不再丢失接管，桌面任务未取得字节前保留浏览器原任务，桌面失败时自动恢复。Blob 下载只在能关联到成功 HTTP 来源时接管。
- LL-HLS 启动时的空清单、PART-only 清单和尾部缺 URI 分片会等待/跳过撕裂快照；直播录制仍支持暂停后收尾合并，Core/安装升级中断会保存检查点并在下次启动恢复。
- HLS/DASH 完成合并后使用最终文件大小；FFmpeg 合并增加时间轴上限、完成校验和错误尾部日志，降低末尾卡住及输出超长风险。
- 已完成文件、HTTP/Torrent 下载中的连续范围、HLS/DASH 已下载分片均可投屏/TVBox 推送；电视端拿到的是受限的本地 LAN 文件/清单，不会重新请求原 CDN 签名链接。
- 删除任务增加终态尾部等待、重复删除合并、Windows 文件锁有限重试；任务列表统一显示“已下载 / 总大小”。
- 修复任务创建时间与 SQLite 默认 UTC 相差 8 小时的问题；覆盖安装显式选择当前版本 Native Host、验证核心文件版本/替换结果，并限制关闭流程等待时间。
- 扩展保留稳定 Chrome key 与 Firefox AMO ID，支持多浏览器同时在线；Firefox 官方安装地址：[HLS Downloader](https://addons.mozilla.org/zh-CN/firefox/addon/hls_downloader/)。

协议边界保持明确：DRM/EME、SAMPLE-AES、未提供可重放请求链的过期签名、封闭 Shadow DOM 中没有 HTTP 归属证据的 MSE，以及需要绕过站点授权的资源不会被强行破解或保存。
