# HLS Downloader v3.0.24

本版本对准 IDM / Gopeed / aria2 一类成熟下载器的热路径：系统代理、跳转后的分段传输、连接复用和任务调度，同时修掉一批会丢进度或把界面卡死的可靠性问题。

- 系统代理模式改为显式读取环境变量和 Windows WinINET / macOS 系统配置（与 Gopeed 的 ieproxy、浏览器一致），httpx 与 curl-cffi 走同一条代理，不再只靠 `trust_env` 漏掉 Clash / v2rayN 的系统代理。
- HTTP 分段请求使用探测后的最终地址，避免每个 Range 都重走 `github.com` 的 302；签名 CDN 过期时从原始链接重新解析后继续。
- 浏览器来源任务的公网 DNS 校验按主机缓存；连接池按并发加宽；无限速时限速器不再给每个分块加锁。
- 并发槽位在登记引擎前先占位，避免排队任务同时越过 `max_concurrent_tasks`。
- 共享 libtorrent session 的 alert 按种子分发，多 BT 并行时不再丢掉别人的 resume / flush 确认。
- DASH 原生引擎补上浏览器 User-Agent；HLS 在没有 curl-cffi 时同样不再发出 `python-httpx`。
- HLS / DASH 分片热路径改为普通 rename，checkpoint 防抖落盘；DASH 恢复直接跳过已校验分片。
- 直播 HLS 并发跟随任务设置（3–16）；合并准备进度按批节流；定时停队不再给无法暂停的解析/合并阶段打标。
- 前端：SSE 干净结束后自动重连、刷新请求串行补拉、暂停行不再显示残留速度、播放按钮只出现在音视频、投屏直链不再空转 share 轮询、全部暂停只针对真正可暂停的任务。
- 浏览器扩展在 request chain 被清掉后仍能按 URL 找到 early takeover，避免同一文件弹两次接管。

验证覆盖 Python 全量测试、前端 Vitest / TypeScript 检查。协议边界不变：DRM/EME、SAMPLE-AES 和已经失效且无法从浏览器重新取得的签名 URL 不会被绕过。
