## 2026-10-19：逐功能静态审查与候选修复（部分验证）

继续对照 AB v1.11.1 的 [BaseHomeComponent](https://github.com/amir1376/ab-download-manager/blob/08bfd440a30d367ae369739d866d30f8c1d4b3af/shared/app/src/commonMain/kotlin/com/abdownloadmanager/shared/pages/home/BaseHomeComponent.kt) 和 [DownloadMonitor](https://github.com/amir1376/ab-download-manager/blob/08bfd440a30d367ae369739d866d30f8c1d4b3af/downloader/monitor/src/commonMain/kotlin/ir/amirab/downloader/monitor/DownloadMonitor.kt)：活动数量与总速度有独立状态流，列表按搜索、分类及队列组合。IDM 的[主窗口合同](https://www.internetdownloadmanager.com/support/using_idm/using_idm.html)则确认状态、分类、列排序和随选择启停按钮这些用户行为；闭源实现无法据此推断其内部性能策略。

本项目侧栏此前按每个状态、队列和分类分别遍历任务，速度更新替换任务快照时会使这些读取失效。本候选仅将侧栏计数集中为一次遍历，并通过 Compose 的结构相等策略，使计数相同的快照更新不使侧栏读取失效。展开态与窄屏图标栏读取同一计数，状态集合、分类函数、队列 ID 与筛选回调沿用原实现；删除原逐项扫描函数，没有引入增量索引、后台线程、定时器或新依赖。

已补充同一任务列表上的响应式回归用例：速度/进度更新、状态/文件分类/队列变化，以及清空列表。已静态更新现有布局断言，差异空白检查通过。相关桌面定向测试及构建已通过，界面沙盒结果见下方 AB 前端章节；侧栏性能收益尚未测量。减少遍历次数不等于已证明整机 CPU、内存或按钮延迟下降；仍需比较小任务库/千任务库，以及侧栏展开/折叠时的实际开销。本批不改变既有发布包及其证据。

### 操作可靠性修复

- 媒体清晰度和种子文件选择此前没有创建中的提交保护。现在提交前同步设置 busy，固定本次选择，禁用提交、取消及选择控件，并暂时阻止对话框关闭；失败后恢复控件并保留选择。复用原有创建状态及自定义控件，没有新增任务管理层。
- Core 的正常 `events` 响应也可能携带 `kind=error`。桌面原来仅在播放和媒体推送等个别调用处检查，其他命令可能进入成功分支。现在统一由 `EnginePipeClient.command` 检查业务错误，并删除原个别调用的重复检查。检查位于完整读取响应、归还连接之后，业务失败不使仍然同步的连接池连接被丢弃；异步种子解析仍由原事件流交付最终结果。
- 选中任务的批量动作和批量删除现在逐项接收错误，单项失败不跳过后续项。处理完本批响应后汇总失败数和首项任务，避免后续成功提示覆盖本批失败。全部开始/暂停继续保持最多 8 项并发；删除成功才移除对应选择，失败项保留供重试。未改变后端动作的合法状态、删除范围或缓存归属规则。

这些结论来自调用路径和差异审查；本批已有编译及协议定向回归结果，但以下业务故障场景仍未实际覆盖。既有 `ProtocolTest` 已覆盖业务错误的代码和消息解析；还需通过真实桌面调用核对统一入口、重复点击、失败重试、混合成功/失败批量以及禁用控件的键盘语义。

### AB 前端参考：排版与反馈（定向验证完成）

产品方向按用户要求确定为：前端参考 AB，功能行为参考 IDM。[IDM 官方主界面说明](https://www.internetdownloadmanager.com/support/using_idm/using_idm.html)明确区分按选中任务可用的动作、停止选中与全部停止、删除列表记录、续传取决于服务端支持，以及确认保存位置。本项目沿用自己的任务状态与协议能力边界；功能对照核对实际效果，不推测 IDM 的闭源实现，也不据此宣称速度、网站兼容性或功能已经完全等同。

用户指定前端参考 AB。本批对照上述固定提交的 `DownloadList.kt`：其任务行使用圆角、选中描边和列布局。借鉴这些可核对的结构，不复制其源码、引入其 UI 库或将本项目专有播放器和浏览器面板描述成 AB 的现有设计。

- 桌面任务行保留 52dp 行高和原列对齐，取消逐行横线，改为带间隔的圆角底色、选中描边与焦点描边。文件名降低字重；状态标签改为较小圆角和次级字号，排队使用中性色；完成进度明确显示 100%。行坐标在外侧留白之后采集，保持右键菜单与点击区域一致。
- 复选框、单选框和开关补可见焦点边框。确定与未知进度条统一圆角轨道和填充端点，沿用已有过渡时长和减少动画设置。
- 播放器播放/暂停、前后 10 秒和关闭使用项目已有矢量图标，播放按钮单独强调，按钮补动作提示。深色播放器的悬停、按压和禁用颜色由播放器自身色板提供；音量文字更明确。准备期间只限制媒体快捷键，不再吞掉 Tab，关闭按钮仍可通过键盘到达。尺寸、动作及播放引擎不变。
- 插件保持 360px 宽：标题最多两行，已加入状态在资源边框与提示中可见，发送/等待确认不会因 disabled 透明度变淡而难以辨认。共享按钮悬停只变色、按压短缩放；更多箭头短过渡，切换面板淡入 120ms，遵循系统减少动画设置。资源卡片不加入随列表重绘重复触发的入场动画。删除只约束旧悬停上移效果的测试，保留级联、焦点和按压守卫。

本批桌面构建与 70 项定向测试、插件类型检查与 130 项测试、双浏览器构建及沙盒 smoke 通过。浅色 JVM 100% 和深色 JVM 150% 下的列表与新建弹窗已检查；插件长标题、复制反馈、Tab/方向键、稳定悬停和浏览器减少动画通过。真实 mpv 两种缩放各 11 项通过，包含子滑块方向键不触发全局快进，以及全屏、画中画、拖动、关闭重开。浏览器 DPR 1.5 是模拟，不是操作系统缩放。

实际右键菜单验收发现 Esc 先被 AWT 全局清选处理消费。只补菜单焦点或列表 preview 优先级都未解决，失败记录保留；最终删除重复的全局清选分支，由任务表处理清选，菜单取得焦点并优先关闭。独立回归确认第一次 Esc 保留选择并关菜单，第二次才清选；该场景加入现有 workbench smoke 脚本，整份广泛脚本未重跑。音量滑块 Right/Home/End 的真实播放器回归已加入现有脚本并在两种缩放运行通过。

见[本批报告及截图](../validation/validation-ab-ui-20261019.json)。未穷尽桌面减少动画、全部禁用控件及播放器提示的绘制；未测量运行占用或安装体积。没有新增依赖或常驻动画，没有生成 MSI、更新 GitHub 或在本机安装产品。当前 Core 源码未在本批重建，前端沙盒集成使用既有基线；其余“待验证”章节保留各自尚未覆盖的运行边界，不因本批前端通过而转为全功能认证。
