# 续传响应身份完整性验收

## 根因与修复

原实现发送 Range/If-Range，并检查 206 的范围起点和总长度，但没有检查响应明确改变的 ETag/Last-Modified。服务器不遵守 If-Range、返回同长度的另一份资源时，仍可能把新内容拼入旧片段并报成功。基于 `3642b43`、只增加回归测试，在 Windows 沙盒实际复现：`changed_206_identity_never_stitches_into_a_saved_prefix` 退出 101，改变 ETag 的响应返回 `Ok(())`。原始失败日志、测试差异和测试程序哈希保存在 `results/`。

修复在写入范围响应正文前检查身份：使用可发送的强 ETag，否则使用 Last-Modified；明确冲突时停止，不发布成品，保留原缓存，报告 `RESOURCE_CHANGED` 并提示新建任务。整任务自动重试不会重复同一个已确认资源变化的请求，队列继续处理下一任务。响应合法省略身份元数据时仍允许续传，不把省略误判为变化。约束依据 [RFC 9110 的 If-Range](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-range)及 [206 元数据语义](https://www.rfc-editor.org/rfc/rfc9110.html#name-206-partial-content)。没有新增依赖、线程或配置。
