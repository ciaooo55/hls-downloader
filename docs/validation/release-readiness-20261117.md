# 7.0.7 正式发布验收计划

## 当前起点

以 `e0a2007a` 后的 7.0.7 工作区和已完成的外部源码整合为起点。Core、UI、插件、真实 HLS 与 curl/FFmpeg 的本机结果见 [整合记录](../architecture/source-integration-20261117.md)。这些结果不替代安装包与浏览器的最终验收。公开版本仍为 7.0.6。

## 执行顺序

1. 核对版本、格式、脚本、功能合同和实际测试入口，修正当前问题，整理发布说明及证据状态。
2. 沿用此前已授权的 GitHub 发布与本地/远端同步流程，将本轮源码冻结到唯一 `main`；不创建平行分支或 worktree。
3. 等待同提交源码 CI、Rust Security、Maintenance Security，并构建同提交 Windows 候选。
4. 用该候选在 GitHub 临时 Windows 环境执行 EXE/MSI 安装、快捷方式启动、升级/回滚，以及 Native Host 生命周期与下载测试。
5. 在同候选上执行真实 Edge/Firefox 媒体、请求凭据、接管归属、回执丢失和重启恢复验收。
6. 执行原生 UI 业务操作、媒体播放、协议/尾块恢复、1000 任务布局及 1/1.25/1.5/2 软件缩放、30 分钟真实持续下载；发现问题后修复并重新冻结受影响候选，不能把旧 SHA 报告算给新源码。
7. 校验最终组件哈希与候选、验收来源一致，才进入正式打包和发布；失败项和未验项保持可见。

## 完成判据与保留边界

- 原有功能入口与持久数据保留，实际场景失败必须解决，不能通过删除功能或放宽结果判定来通过。
- 正式发布要求同源 CI、候选、安装、浏览器、原生扩展验收，以及可追溯的文件哈希；本地测试数量不是发布凭据。
- 不操作个人桌面或浏览器。UI/安装/浏览器只使用已有 GitHub 临时 Windows 流程。
- 沿用用户已明确的范围：Windows 未签名手动安装；Firefox 提供待 Mozilla 签名包和源码；真实投屏/TVBox 接收端、付费云端字幕质量及物理多显示器验收不虚记通过。功能继续保留，不能宣称所有外部设备、网站和云服务都已实测。
- 上轮被策略拦截的五个测试夹具原地保留，本轮不绕过该删除拒绝。

## 当前发现

- 本机开发构建已通过，但尚无覆盖本轮 7.0.7 的最终发布证据；正式门禁正确拒绝缺失的 `release-evidence.json`。
- 外部新增 Rust 测试仍有 rustfmt 差异，会阻止 CI，先按项目格式修正。
- 发布说明仍混合外部历史分轮记录与已过时的功能差异，需要整理为当前实现及真实验收边界。

## 发布收敛补充

- 初次冻结 `28aca86f` 的 Core、插件、Compose、合同与两项安全检查已成功，原生 Presenter 和候选仍在构建时，发现 hosted 扩展验收遗漏已有 `--local-ftps` 入口。补接该入口及 pyOpenSSL，并加入显式/隐式 FTPS 的 5 MiB 四连接、暂停、REST 恢复和完整字节校验；服务器记录必须证明至少两条连接实际请求数据。证书只在隔离 runner 创建并在 finally 删除，不操作个人证书库。这一变化需要重新冻结候选，旧报告不作同源正式证据。
- 本机对已验证的 7.0.7 开发测试二进制执行五轮 32 MiB HLS 单分片测试，中位数 0.723151 s、44.251 MiB/s、进程 CPU 0.03125 s；全部逐字节校验通过，可靠同步保持开启。结果在 `artifacts/release-readiness-20261117/hls-benchmark/benchmark.json`，受测 SHA256 为 `3bd0f7492c3a74cc5a7a3591977e536e17ef408e3c8e73f5ceda1f8169690cbe`。退出后未取得有效峰值工作集，字段为 null，不能声称完成内存比较。
- 历史基线 EXE 的实际哈希已与旧报告不同，无法开展可信的本轮 A/B。当前单分片完成吞吐高于既定 20 MiB/s 本地阈值，但不据此宣称消除全部性能回退或达到 IDM；正式候选仍必须通过独立环境持续下载和帧时间门禁。

## a56ddefd 候选实际验收与修复

- 候选 `44082255251` 成功：Portable 升级/回滚、打包组件、MSI 升级/失败回滚、EXE 默认安装及中文自定义路径快捷方式启动、schema 6→7 迁移、不支持的 schema 明确报错且保全数据库均通过。
- 浏览器 `44088404567` 的 Edge/Firefox 各 24 项媒体识别、请求凭据和响应归属、Firefox 重启恢复、实际 Host/Core 交接均通过。弹窗验收失败原因是新版 CSS 分隔符不在 `textContent` 中，日志实际为 `音频.wav15.7 KB`；改查语义 `aria-label` 并核对可见信息项，不取消布局、浮窗操作及菜单键盘检查。
- 原生 `44088414238` 的 13 项 UI 业务、媒体播放、18 项依赖专项、真实 HLS curl 媒体、FTP/FTPS/SFTP 等 18 项协议、HLS/DASH/live/音轨恢复及公网 HTTPS 通过。1000 任务的帧间隔 P95 为 15.978 ms；四档软件缩放和三种窗口尺寸通过。截图及原始报告在本轮 `native-gui/`、`native-acceptance/`。
- 尾块测试 45 次成品哈希校验、直接 HTTP 和 WinHTTP 暂停续传通过；崩溃恢复失败：52 MiB 已同步的范围存在，但 SQLite 周期进度尚未提交，重启快照显示 0 字节。修正启动恢复：在发布 paused/queued 状态前，按原地址、格式、总长、文件长度和去重范围重建已落盘字节数；HTTP 恢复仍须重新探测服务器身份。增加数据库重开及截断、越界、错误资源、旧格式、空范围回归。
- 因上述失败，30 分钟持续下载刚开始时主动取消，未计通过。该 SHA 不发布；修复后重新冻结并完成同源全流程。
- 五轮同一二进制开关对照：均速完成约 1.438 s；慢尾直接 HTTP 从关闭拆分的约 5.04 s 降至默认拆分 2.024 s，WinHTTP 约 5.05 s 降至 2.028 s。这只是规定 loopback 场景，不是 IDM、互联网或版本间性能对标。
- 修复后本机真实 Core 强杀恢复：直接 HTTP 与 WinHTTP 均恢复 54,525,952 字节，续传服务器分别只发送 12,615,681 / 12,648,449 字节，最终 64 MiB 文件 SHA256 一致。报告为 `crash-recovery-fixed.json`。新增恢复边界回归、19 项检查点回归及范围续传测试通过；新 Core 开发构建成功。没有使用个人桌面或浏览器。
