# 任务列表可靠性：按实际结果修复（2026-10-27）

本轮继续对照下载器的任务管理行为，修复实际失败的数据往返和批量操作边界。功能范围仍以[现有 29 项审查表](../../architecture/performance-audit-20261018.md)为索引；本报告不把局部结果扩展为所有功能、性能和交互均等同 IDM/AB。

## 根因与改动

1. JSON 导出不限制数量和大小，导入却限制 100 项、1 MiB，程序能生成自己无法导入的文件。现统一为最多 1000 项、1 MiB，导出超过限制会提示分批选择；直接解析入口也检查字节上限。
2. TXT 链接读取到 100 条就直接返回，用户看不到后面的链接被丢弃；`.urls` 则落入单链接解析，只读第一条。两种纯文本列表现在最多读取 1000 个不同链接，超限明确失败，不创建截断列表。HTML/媒体嗅探原有 100 项限制没有扩大。
3. `ImportPaths` 的循环用 `?` 遇错直接退出。前面可能已有持久任务，后面的文件却从未处理，调用者只收到错误。现在继续后续文件，保留成功事件，最后发出带成功数量和失败序号的业务错误；桌面现有业务错误处理会显示该信息。
4. 实际跨任务库验收发现，JSON 的旧绝对下载目录被新环境的根目录限制拒绝，整批创建 0 项。这不是测试期望错误。导入现在保留当前根目录内的合法子目录，原电脑的其他目录改用当前设置的默认目录，仍拒绝 `..` 路径。
5. 源码的旧 `release_ready=true` 与目前候选验收状态不一致，已设为 false，避免按旧标志进入正式发布门禁。

未增加依赖、常驻线程、计时器、播放引擎或浏览器权限。对标的是行为和实际结果；[IDM 官方主界面文档](https://www.internetdownloadmanager.com/support/using_idm/using_idm.html)用于核对选择范围、任务管理和错误语义，不推测闭源内部实现。AB 的既有源码及界面对照见原审查表，本轮没有新 UI 代码或 AB 实测。

## 验证记录

- 旧生产逻辑加新增回归，在沙盒中实际失败：JSON 6 通过/2 失败，批量导入 1 失败。失败原文保留在 `results/before`。
- 第一版候选完整 Core 回归通过，但实际跨环境重新导入失败。原始失败报告保留，随后据此修复目录归属问题。
- 最终源码离线构建 Core/Native Host/Updater；沙盒 Core 回归 **641 通过、0 失败、12 项按原配置忽略**。没有将忽略的场景写成通过。
- 实际 IPC 导入 1000 项，导出 621,656 字节 JSON，再导入不同默认目录的全新任务库，任务数、URL、计划时间一致。混合三个文件（正常/无效 JSON/正常）会报告中间失败，两个正常任务均实际下载，成品 SHA256 与源内容相同。
- 既有 HTTP 边界脚本通过，包含实际 POST 正文、跳转身份、HTTP 错误、写入错误、暂停及 Core 重启后的续传和哈希核对。它不是全浏览器或全部协议实测。
- 另用缺少目录修复的中间程序复现：创建 0 项、明确返回“下载目录必须位于默认下载根目录内”。初次独立运行缺少 MSVC DLL、IPC 未就绪的夹具失败也保留；补齐既有运行依赖后才记为根因复现。

使用方法和限制见[任务列表导入导出](../../guides/task-import-export.md)。JSON 不保存凭据、POST 正文、分片和队列定义，公共 GET 往返验收不能证明这些请求也可完整迁移。
