# HLS 分片失败的重试边界

## 根因与修复

原有分片重试将网络请求、解密和写盘放在同一循环中，除暂停/取消外全部重跑三次。明确的权限拒绝、资源失效、磁盘写入失败和无效密文因此都会重新请求资源。字节范围响应还把“需要 HTTP 206”放在实际返回码前，公共错误诊断会误提取 206，使真正的 503 被当成不可恢复错误。

现在只对可恢复的网络失败重试；HTTP 状态复用普通下载的既有策略和状态提取函数，不增加第二套状态解析。字节范围错误先记录实际 HTTP 状态，错误的 Content-Range 不重试，正文截断允许重试。解密在内存中完成后再写盘，写盘及解密错误不再触发重新下载；删除了旧的重复执行函数。退避复用已有的可中断等待，保留暂停/取消原始信号。

分片 worker 确认失败后清空尚未领取的共享队列；已经在下载的分片仍完成原有回收和 checkpoint 流程，不修改主任务控制文件或丢弃已完成分片。这部分通过调用和锁顺序复核；本批没有新增确定性并发调度测试，不能据此宣称所有在途请求立即取消。

通用传输既有的 403 浏览器身份回退仍保留。包含 curl 的 HTTP 夹具对 403 实际产生两次传输请求，但不再在分片层整轮重试；不能把一次分片尝试说成永远只有一个网络请求。

## 实际验证

旧生产逻辑的真实本地 HTTP 回归在沙盒退出 101：401 分片请求三次，期望一次。修复后的场景覆盖普通及字节范围请求的 401/403/404/410/416、503 恢复及耗尽、正文截断、不支持 Range、写盘失败和解密失败，核对实际请求次数和输出内容。401/404/410/416 一次，带既有身份回退的 403 两次，503 最多三次，截断后第二次恢复，写盘/解密失败只取一次且不发布无效分片。

首次定向运行发现测试未考虑安装环境的既有 403 传输回退，修正测试预期，未移除兼容行为。首次完整 Core 运行有 631 项通过、1 项失败、9 项跳过，失败是测试程序旁没有托盘图标；补齐源码中的运行资源后重新执行整套，632 项通过、0 失败、9 跳过。再显式执行 curl 2 项、WinHTTP 3 项，均通过，共 637 个不同回归。还未运行扫描器超时、真实 FFmpeg 回收、伪装 HLS 音频解码和交互 UAC 退出码这四项外部环境测试；没有将跳过项计为通过。

最终 release Engine 已构建。新增最终安装包分片验收使用公开 WebM 的字节作为 HTTP 分片夹具，核对普通/范围 403、503、截断恢复和完成/删除后的缓存，属于下载、文件一致性与清理验证，不属于 HLS 播放格式验收。最终 MSI 安装验收尚待执行，不能视为通过。

## 范围与保留问题

不在宿主安装或运行产品，不调用云端，不重试此前被拒绝的直播录制。UI、插件和其他原生组件未修改，后续候选复用已验收组件；没有新 UI、真实浏览器、收费字幕或实体投屏验收。指定直播站点 403、原始 HLS 卡死现场和上一批首次安装启动超时根因仍未闭环，没有新增 IDM/AB 同条件性能达标证据。

本轮脚本、测试程序和构建文件复用项目内 `.tool-cache`。历史缓存删除曾被自动审批拒绝，没有换工具或路径重试，工作目录仍不是只有源码。既有用户备份及宿主任务、下载、密钥、安装和注册表未操作。
