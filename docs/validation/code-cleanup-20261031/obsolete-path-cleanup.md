# 旧路径收敛（第六轮）

本轮从 `b78af25b` 的干净工作区继续，按当前入口、调用方及数据依赖判断删除范围，没有新增功能或兼容接口。

## 删除与修复依据

| 区域 | 核对依据与修改 |
| --- | --- |
| 下载限速 | `ThrottleState.legacy` 的唯一配置函数被 `cfg(test)` 排除在生产构建外，运行时永远是无限速桶。删除该桶、仅测试使用的配置函数和 `consume_bucket` 的可选 scope 分支。没有下载上下文时直接返回；有上下文仍依次使用现有 global/queue/task 桶与小时额度。已有聚合限速、动态配置、队列同步及额度测试继续保留。 |
| 接管窗口身份 | Presenter 的领取、显示回执、续租三处均发送实例 ID；Compose 只以 `ok=false` 请求故障回退。删除空 ID 被映射成 `legacy-presenter` 的旧分支；`ok=true` 缺身份时拒绝，不能占用租约或修改持久行。空 ID 的主窗口回退仍受现有租约检查。客户端将带默认成功参数的 `presentHandoff` 收窄为唯一实际使用的 `claimHandoffFallback`，原方法移除。 |
| 资源分类 | 当前 Rust `ResourceKind` 只有 file/hls/dash/live/ftp/sftp/torrent，Host 将扩展内部的普通 `media` 资源归一为 file；工作台从 Core 接收序列化资源。删除 UI 单方面保留的 `media` 短路与专门保护该旧值的断言，保留跨语言分类表及当前媒体类型测试。 |
| Native Messaging 分派 | 全部活动客户端与脚本未发送 `push_to_tv`；`wait_handoff` 仅剩桥接优先级分支及一个超时测试。删除这两个操作别名和 `push_to_tv` 类型别名，超时测试使用当前 `handoff_status`。移除与 match 重复的操作白名单，由单一分派表直接拒绝未知操作。`download` 仍由当前验证脚本消费，因此保留。 |
| 投送类型 | 当前扩展两个实际入口分别明确发送 `cast`、`tvbox`。Host 原先把缺省或任意未知类型静默变成 cast；现在在创建请求、唤醒 UI 前拒绝无效类型。新增回归检查无持久记录和 UI 请求标记变化，没有执行真实投送。 |
| 扩展类型声明 | `HandoffPresentationMode` 列举旧模式后又并入 `string`，没有形成实际限制，且无其他导入。删除该别名，字段直接使用 string，消费方仍仅判断真实使用的 `none` 值。 |

本轮修改 9 个活动代码/测试文件，没有增加生产模块、配置、依赖或协议版本。既有任务目录、设置和数据库导入路径涉及实际持久数据，没有按名字含 legacy 就删除。复用、故障恢复与历史接口兼容按实际用途区分，不把所有 fallback 都当成废代码。
