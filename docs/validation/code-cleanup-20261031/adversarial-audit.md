本轮从 `9c34f2c0` 开始，起始工作区干净。复核上一轮 419 个活动文件清单的工作树字节哈希：**402 个文件未变，17 个文件修改**。修改文件的前后哈希见 [本轮源码变更清单](adversarial-source-changes.csv)；原始全量清单及静态检查方法保留在 [第三轮报告](module-audit.md)。

## 实际修复

| 问题 | 具体影响与修改 |
| --- | --- |
| 抓链切断 UTF-8 | 未加引号的中文 href 会在字符内部切片并 panic；无分隔符长 Unicode URL 也可能在第 2048 字节切片。按字符边界与实际分隔符解析，支持不带引号的 href；超长裸链接整条跳过。 |
| BT Windows 路径边界 | 原谓词接受盘符路径、ADS、尾随空格及 DOS 设备别名。拒绝这些组件；普通下载与 BT 共用 `output_path` 的设备名校验，补上 Windows 的上标数字 COM/LPT 别名。发布前复用目录边界检查，拒绝现有目录联接指向根目录之外。 |
| bencode 不受控递归与整数回退 | 128 层输入原先未受限，错误或溢出整数被静默转换成 0。增加 64 层解析边界，拒绝无效数字、前导零、负零、超出 i64 范围的整数及重复字典键。保留 `parse_value` 返回尾随块的协议合同。 |
| BT 长度和文件偏移 | 多个大文件长度相加会溢出；丢弃非法路径组件、跳过缺路径文件会让后续文件映射到错误偏移。使用受检加法，拒绝畸形条目与大小写冲突的重复路径，保留零字节文件及正确偏移。 |
| info-hash 取错内容 | 注释含 `4:info` 时，全文搜索误取注释内容。现在遍历顶层键值，取得真实 info 值的原始字节区间求 SHA-1，避免重新编码改变哈希。 |
| BT 发布提前破坏旧文件 | 原实现先截断成品，再发现临时数据不足。现在预检所有所选范围，将每个文件完整写入独立暂存目录并同步，再复用现有覆盖/回滚发布。短数据拒绝前不修改任何所选成品；中途失败时已发布的完整文件可保留，不宣称整个多文件种子是一次原子事务。 |
| 元数据先全量读入再处理 | 播放清单与字幕限制 8 MiB，AES-128 key 限制 16 字节，种子限制 16 MiB；HTML/Metalink、更新 JSON、DLNA 描述与 tracker 响应限制 1 MiB。按 Content-Length 提前拒绝，同时最多读取上限加 1 字节，覆盖未知长度/分块正文。cURL 回退沿用已有传输中大小监测；其磁盘写入可能在两次监测之间短暂超过阈值，不宣称磁盘零超额。 |
| 本地导入文件读取竞态 | 链接文件与任务 JSON 保留原 metadata 预检，并增加读取过程限制，防止检查后文件增长导致无界分配；分别沿用 256 KiB、1 MiB 上限。 |
| 扩展超限响应未释放 | 原实现发现 Content-Length 超限直接返回，未取消正文传输。现在先取消 body，即使取消失败也返回拒绝结果。 |

种子读取的两个当前调用合并到一个有明确用途的函数；移除迁移后没有调用方的 `fetch_bytes` 无界接口及其导出。普通 HLS 分片仍使用原传输路径，没有把元数据限制误加到视频内容上，也没有新增依赖。

协议依据：[BEP 3](https://www.bittorrent.org/beps/bep_0003.html) 要求 info-hash 对原始 info 字节计算，整数禁止负零与前导零；本实现的 i64 和深度边界是产品支持限制。[BEP 9](https://www.bittorrent.org/beps/bep_0009.html) 的消息头后可带原始 metadata 块，因此不能对所有 `parse_value` 调用强制要求输入无尾随字节。

## 对抗验证与最终门禁

修复前实际运行并复现了 **5 项新增 Rust 测试失败**，覆盖 Unicode panic、路径谓词、嵌套/整数、长度溢出及 info-hash；见 [修复前输出](adversarial-red-tests.txt)。扩展新回归也在修复前失败，原因是超限响应未取消。

新增 bencode 确定性语料包含 **1176 次解析调用**，覆盖截断、逐字节突变、字典嵌套和重复键；这些调用属于一个测试，不换算成 1176 个独立测试。ZIP 现有测试增加中央目录每个截断位置和名称/extra/comment 长度溢出样本。HTTP 回归覆盖已声明超限、未知长度、chunked、恰好上限、截断及无正文 304。

首轮扩大库测试是 668 通过、1 失败、12 ignored、4 filtered。失败的旧哈希测试构造了缺少文件长度的无效种子；修正为有效的空文件种子，并将“哈希长度为 40”加强为实际摘要校验。原失败输出继续保存在工作区诊断目录。

检查还发现仅验证输入的若干测试会启动后台下载。对应对抗测试及“开始前选择文件”测试改为创建暂停任务；后者在清理前释放 coordinator，并让清理失败显式报错。
