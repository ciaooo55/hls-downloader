## 实际修复

1. **远程 ZIP 空目录读取**：`Source::bytes` 在检查边界后直接返回空字节，避免空读取生成 `bytes=0-18446744073709551615` 等非法范围，或无意义地要求资源身份。新增测试同时验证越界的空读取仍被拒绝。
2. **分段图的首个未完成字节及溢出**：持久化范围已转成半开区间，fallback 活动位置不应再加一。修正显示偏移，消除异常检查点的 `u64::MAX + 1` 溢出，新增正常及异常范围回归。
3. **元数据无正文响应**：HEAD/304 共用正文判定，用于读取上限、完整长度与读取循环。304 的 Content-Length 可以描述资源大小，不应当作即将读取的正文长度拒绝。一个回归测试覆盖 HEAD、304、正常正文、超限正文和截断正文五种响应。
4. **模块职责与依赖方向**：下载目录约束、逻辑规范化及越界检查从下载协调器移入已有 `output_path`；对应路径测试一起迁移。队列时间窗判定移入已有 `net_policy`。抓站调用这两个策略模块，并移除重复的队列 enabled 判断；未增加转发层或兼容包装。
5. **Host 与控制流**：两处只需最后一个有效交接记录的查询使用双向迭代器反向寻找，避免逐条反序列化全部记录。压平 CLI 句柄校验与抓站条件；元数据循环只在确有正文时进入。
6. **重复测试与无用导入**：将 NativeBridge 标题/Unicode 边界测试并入同模块测试文件，删除重复 FakeEvent/FakePort，保留原测试。删除五个经 AST 及调用核对确认无用的 Python import。
7. **持续门禁**：PowerShell 默认语法检查纳入 `.psm1`/`.psd1`，当前实际覆盖 60 个文件；CI 纳入公共 Python IPC 的七项测试、轻量 Rust profile 的全目标严格 Clippy，并取消全局 `dead_code` 忽略。
8. **格式收敛**：修复现有 Rust 格式门禁差异。16 个仅有格式变化的 Rust 文件经“对起点源码执行 rustfmt，再与修改后内容比较”确认一致；没有借格式整理改变其行为。

## 重复与引用候选的处理依据

12 个非空行、至少 400 字符的跨文件完全重复窗口，合并 NativeBridge 测试前有 31 个，之后有 28 个；这些数字是重叠窗口，不是独立缺陷数量。核对后剩余类别为：

- 图标源文件的上游许可证声明：保留原声明。
- 两组持久化测试的延迟写屏障：各自继承的存储夹具有不同的键读取和对象更新语义，保留局部实现，避免为少量测试代码引入策略包装。
- Core 与独立更新器的 WinTrust 初始化：各自承担当前签名授权边界，沿用首轮核查结论。
- 浏览器媒体推送 wrapper/core 的参数声明：公开入口合同需要一致，保留声明，不增加动态参数生成。

生产函数引用扫描候选经核对为测试或 trait 回调，未据此删除系统入口。构建消费的协议/扩展身份常量继续保留。当前 Python AST 扫描没有剩余未使用 import 候选；Rust 全目标检查未报告 `dead_code`，TypeScript 保持 `noUnusedLocals`/`noUnusedParameters`。这些工具不证明所有公开导出都必有业务调用。
