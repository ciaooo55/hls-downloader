# 2026-10-25：浏览器请求身份、可中止传输与媒体完整性

## 根因与修复

HLS 的浏览器传输路径在第一次请求前无条件删除 `__cf_bm`、`__cflb`。这会改变插件保存的实际请求身份。根据 [Cloudflare 官方 Cookie 说明](https://developers.cloudflare.com/fundamentals/reference/policies-compliances/cloudflare-cookies/)，`__cflb` 用于保持源站会话亲和，并非凭名字就能认定的过期风控数据。本轮首次 curl 请求完整保留经过 URL/域/目录作用域选择的 Cookie；既有收到 403 后的 `__cf_bm` 恢复路径保留，但不再删除源站亲和 Cookie。

旧 curl 使用 `Command::output()` 阻塞等待整个传输，期间不读取任务暂停/取消状态。现在直接等待子进程退出事件，最多每 100 毫秒检查控制文件，暂停/取消时终止并回收该子进程。进程一旦退出会立即唤醒，不给每个小分片固定增加 100 毫秒。取消信号向上传递，不再被浏览器优先路径吞掉后启动另一套网络传输。

旧代码只在 curl 非零退出且没有 HTTP 状态时报告错误：收到 200 后正文断开也可能作为成功响应交给 HLS。本轮将 curl 非零退出按传输失败处理；统一媒体实体读取也核对完整正文长度，避免其他传输路径接受同类残缺正文。错误、暂停、取消、启动失败时清理本次 curl 临时目录；成功响应目录继续由既有文件正文对象持有并在释放时清理。输出写临时文件，避免等待退出时错误管道填满；没有新增依赖、线程池、服务或配置。

这修复了可从代码和受控服务验证的请求语义、控制与完整性问题。指定直播站点的 403 尚未闭环；没有将 Cookie 修复推断成该站点的实际录制已成功，也没有重试此前被自动审批拒绝的录制。
