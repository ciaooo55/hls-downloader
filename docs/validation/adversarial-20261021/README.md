# 五轮对抗验收与交付核对（2026-10-21 至 22）

本轮在 Windows Sandbox 中运行生产组件、浏览器和竞品，宿主没有安装产品。没有签名、上传真实云端字幕音频或验证实体投屏/TVBox 接收端。

## 实际修复

- 限速、小时配额等待期间未检查暂停/取消，导致任务看似暂停但工作线程仍占用。等待现在分段检查控制状态并重新读取限制；HTTP 保留续传检查点，HLS 子请求继承父任务控制，FTP/SFTP/BT 使用同一控制约束。没有给无限速热路径增加控制文件轮询。
- Native Pipe 的等待与打开之间存在竞争；其他客户端可能先占用实例，导致 Windows 错误 231。改为先打开，仅在实例忙时按原总超时重试。旧二进制的并发回归实际失败，新二进制通过。
- 安装器把已带 BOM 的停机脚本再加一次 BOM，Windows PowerShell 5.1 无法解析开头的 `param`，覆盖升级和卸载报 1603/1722。释放脚本时先去掉源文件的 BOM，再写入唯一 BOM。失败日志保留真实错误，成功日志删除。
- 此前已实现的字幕音轨归属、失效上下文释放、下载状态及清理边界纳入本轮回归；生产改动与测试前置条件修正分别保留在 Git 历史中。

另从旧包安装并建立真实暂停任务，在旧 UI/Core 保持运行时覆盖升级：只剩新产品登记，原安装路径保留，暂停任务恢复后文件哈希一致且缓存移除，卸载移除程序和登记但保留用户成品。原有失败安装日志没有改写为成功。

安装内容约 447.7 MiB，222 个文件。主要是 FFmpeg 157.5 MiB、libmpv 114.2 MiB、JRE modules 51.5 MiB、Presenter 27.4 MiB、Core 14.0 MiB 和 Skiko 13.5 MiB。它们是运行依赖，不是下载分片。此轮未新增播放引擎或依赖，也未删除编解码能力来缩小体积。

## 真实网页与边界

- Firefox 的接管测试覆盖响应前拦截、用户给出的 GitHub EXE、接受/拒绝、错误恢复、跨域与重复确认；检查浏览器下载创建事件和磁盘文件，不靠擦掉历史掩盖下载。
- Firefox 可在符合条件的 GET 下载导航创建下载项之前交接；Chromium MV3 当前仍采用创建后暂停再交接，不能保证浏览器完全没有下载事件。POST、Blob/data 下载仍需浏览器先保存再导入，避免重复提交或丢失本地导出。
- hls.js 官方演示和 MDN 视频在 Edge、Firefox 均实际播放并识别到正确资源。DASH 公开 CDN 样例未播放，原 Edge 记录 CDN 连接被关闭。全新浏览器配置、不加载本插件的 Edge/Firefox 对照也未播放，`readyState=0`；这说明基线本身未成功，不能把该样例算作插件识别通过，也不能据此定位所有失败的唯一原因。
- 用户给出的网站停留在 Cloudflare 安全验证，没有暴露播放器；未绕过安全验证，只保存脱敏观察，不能证明该网站已修复。
- 字幕元素采集、预取、生命周期及主程序配置联动有受控测试；本轮没有真实云端上传，不能证明当前服务可用性、识别准确率或翻译质量。
