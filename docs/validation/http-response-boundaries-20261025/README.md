# HTTP 畸形响应与空连接池记录修复

本轮定位并复现两个问题，没有增加生产依赖、后台进程、轮询或配置项。生产代码改动限于 `native_shell/src/http_engine.rs`。

## 根因与修复

`parse_content_range` 对服务端字符串直接取前 5 个字节。响应头包含 `byte界 0-7/8`，或无效 UTF-8 解码后的 `byte� 0-7/8` 时，第 5 字节可能落在字符内部，触发 Rust panic。改为安全读取 ASCII 单位前缀，畸形内容继续返回原有的无效 Content-Range 错误，不吞掉错误、不伪造下载成功，正常 RFC 和既有裸范围格式不变。

WinHTTP 空闲连接池仅限制空闲句柄总数和每站点数量，但取出最后一个句柄时保留空 Vec 和站点 key。不断访问新站点时，空站点记录可绕过句柄数量限制累积。现在取走最后一个句柄便删除空记录；连接归还时仍沿用原有复用和超限关闭行为。这里限制的是空闲池的站点记录，不是把全产品活动连接总数限制为 32。

扩展两个现有回归，先在未改生产逻辑的测试程序中复现：解析用例发生字符边界 panic，连接池用例发现空站点记录，均退出 101。修复后正常格式、非法格式、句柄不重复借出、每站点上限及连续 1024 个不同站点的空记录清理通过。原始失败和成功日志均在 [results](results)。
