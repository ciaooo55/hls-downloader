# 2026-10-25 弹窗绘制、直播识别与播放器资源归属

本轮在原有 `main` 工作目录修复，没有创建分支或 worktree。产品仅在 Windows Sandbox 中运行；未安装、更新或结束宿主 `E:\hls` 的程序和下载任务，未签名，未调用收费云端。

## 修复及根因

**弹窗残缺已复现。** 旧 Presenter 在 125% DPI 下第一次下载完成时绘制正常，第二次重新显示完成窗时仅文件名区域被重画，背景、标题和底部按钮消失。证据是 `results/repaint-baseline-final/complete-1.png`，原报告判定失败。Slint 1.17.1 的 Win32 softbuffer 在窗口隐藏后可能仍报告旧缓冲可复用，局部绘制遗漏了被系统清空的内容。

重新显示窗口和调整原生裁剪区域时清空局部绘制缓存并请求完整重画；普通进度更新保留局部重绘。第一版候选过早在首次高 DPI 创建时调用快照，触发渲染缓冲尺寸断言，未交付。最终版本先核对原生窗口与 Slint 的物理尺寸一致，避免这一初始化时序问题。没有增加渲染引擎、依赖或常驻轮询。

**直播识别不再只依赖插件的类型标签。** 对照 v3.0.39，最终媒体清单没有 ENDLIST 或存在已录制时间轴时按直播处理；主清单 URL 本身不足以判断。直播暂停或失败时，已完成的本批分片也写入原子时间轴，用于恢复和去重。进度事件把自动识别的直播状态传到 Core；插件已确认直播时明确传递 `live` 类型。暂停仍保留续传语义，未改成隐式结束录制。

**插件减少误报及无用浮窗。** 默认角标和菜单列表只显示关联到实际播放来源的媒体；点击“嗅探全部资源”才显示全部候选。浮窗只出现在鼠标所在播放器，未匹配来源时不显示不可操作的“正在识别”按钮；移开后隐藏，跨按钮间隙、键盘焦点和拖动期间保持可操作。Firefox 实测另复现了焦点释放后浮窗滞留：鼠标已在播放器外且不再产生移动事件时，原逻辑没有重新判断归属；焦点/悬停保持期结束后现在重新判断鼠标位置。后台仍被动收集候选，并读取解析播放器归属所必需的清单元数据；本轮没有把全部网络观察都关闭。

## 未完成及限制

本机两条旧直播任务在抓取清单时收到 HTTP 403。现有证据不能确定是身份、链接时效还是服务器策略。用户提供的新网页在沙盒可见 Edge 中已经实际播放，当前媒体清单多次返回 HTTP 200；该观察没有保存带签名的媒体 URL、Cookie 或请求身份，摘要见 `results/live-site.json`。

随后使用当前请求执行真实直播录制的命令被自动审批拒绝，仅返回 `blocked by policy`，未提供具体原因。没有改用其他通道执行同一动作。`scripts/validation/smoke_v7_live_site.py` 已编写但尚未执行；因此不能称该网站的下载器 403 已修复，交付保持候选状态。

本轮原生鼠标自动化工具的 native pipe 不可用，按工具规定恢复后仍失败，未改用其他 Windows 输入注入。弹窗确认由 Core IPC 完成，截图使用只读窗口捕获；这不能冒充原生按钮点击验收。未重跑全部功能、收费字幕、投屏/TVBox、长时间稳定性或全部网站，也未改变 Chromium 下载接管的浏览器 API 限制。

构建来源、具体组件哈希和源码补丁保留在 `results` 及桌面 `BUILD-PROVENANCE.json` 中。桌面交付、同步和清理的最终状态见同目录 `delivery.json`。
