## 根因与改动

- Host 原先分开执行“查询请求ID→保存交接→登记运行态”。两个Host可同时读到不存在并分别创建交接；保存后、登记前退出也会留下未通知运行态的交接。现由 `admit_handoff` 在唯一Core锁内查重，并在同一SQLite事务提交交接行和事件检查点；持久化失败同时回滚运行态。
- 请求ID相同的重试只取得原回执，已接受/拒绝的请求不会重新弹出或新建任务。首次和重试均返回规范化的持久化格式。交接编号已属于另一请求时拒绝覆盖。
- Host 的交接及凭据编号原来只有毫秒时间和进程内序号，多个Host同毫秒启动可能冲突；现加入进程ID。事务失败有明确拒绝才回收本次凭据；传输断开无法证明未提交，保留可能已被接收的上下文。已提交结果不因未使用上下文回收失败而变成浏览器回退。
- 插件在写本地请求日志后、发送前退出，原来会持续查询空结果。现在空查询可用 `recover_offer` 重新提交**原请求ID**到上述原子接收入口。查询失败保持未知；旧Host不支持新入口时保持未知，不退回旧接收实现；空成功应答也不能被当成所有权回执。
