## 已复现的根因

1. Core 已持久化 offer，连续两次成功回执被传输错误替换后，插件把未知结果当拒绝并恢复浏览器。修前下载所有权回归17项中2项失败；修后按原 `client_request_id` 只读查询，不再发新 offer 或自动恢复第二份传输。
2. 直接下载的未知交接仅存在活动 worker 内存中。新增回归实测后台重载后发出了第二次 offer（21项中1项失败）。修为发送前保存摘要和请求 ID；恢复时查询原交接，持久化失败不发送。原单测仅保留模拟会话存储，进一步按实际扩展重载会清空 session 的边界修为 `storage.local`；不保存 URL、Cookie、正文或密钥。
3. 直接链接在离线 ping 后原本直接回退，没有先检查之前的未知交接。现在先读记录；已存在记录时只查询，离线不重放。全新且尚未发送的请求仍可回退。

未知结果的提示改为“已停止自动回退”，不再声称保留了 Firefox 的原响应。Chromium 暂停项使用已有持久恢复队列，待真实交接回执返回后处理；查询为空不证明先前超时的 offer 永远不会提交。
