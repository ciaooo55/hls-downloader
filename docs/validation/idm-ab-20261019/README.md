# IDM / AB 成品对照（2026-10-19）

这份记录覆盖本地 Windows Sandbox、默认配置的普通 HTTP 下载与全产品进程资源，不能解释为全功能对等或公网测速。未在本机安装/运行产品，没有云端调用、签名、发布或新 MSI。

## 方法和成品正确性

官方 IDM 6.43 Build 15、AB Download Manager 1.11.1 与本项目候选依次运行，三轮轮换顺序。高速资源 128MiB；限速资源 64MiB，每条服务端连接限制为 4MiB/s、响应头前延迟 80ms。服务器也在同一沙盒；沙盒分配 6144MiB、禁用外部网络，loopback 可用。每轮启动后等待 8 秒，再采样 5 秒空闲状态。每次仅在预期路径生成完整长度且 SHA-256 一致后记为成功。

`comparison-clean.json` 中 18 个样本完整，均通过成品哈希校验。三款仍使用各自默认连接策略，没有完成同连接上限对照，也没有测按钮点击延迟。样本波动较大，不能只取最好成绩推断一般性能。

本项目在本次限速场景仍落后于 AB，CPU 和内存也没有达到 IDM 水平。高速样本的区间相互重叠，不能据中位数宣称本项目普遍更快。`metrics.json` 保留最小值/最大值及服务端 body 写入字节；这些字节不含协议头，不能当精确线速流量。

运行映像占用：本项目 472,811,891 字节、AB 172,564,357 字节、IDM 26,044,102 字节。本项目映像是 r12 基础映像替换候选 JAR/Core，未生成新安装包；播放器和 FFmpeg 等功能差异意味着这不是相同功能集合的体积比较。安装字节也不等于运行内存。

## 保留与撤回的改动

HTTP 普通范围领取改为一次排序、取队尾，取消待办范围副本，线程数量不超过实际范围数量。播放优先跳转仍可拆分尚未发出的范围，回归检查覆盖连续性及无重叠。这项改动减少了队列扫描和分配，但本次横向结果不能证明它单独改善了吞吐。

初始连接数从 2 提高到 8 的实验已经撤回。实验三轮中有较快的热样本，也有明显更慢的样本；证据不足以作为默认配置变更的依据。`comparison.json` 保留该实验，不能当最终三款对照报告。

Core 初轮及最终保留方案分别为 613 passed / 0 failed / 4 ignored，最终一轮耗时 49.63 秒，退出码 0；六类媒体下载、续传、播放和清理 27 项通过，HTTP 边界 13 项、停滞恢复 6 项通过。`download-playback.json`、`http-boundaries-final.json` 和 `http-stall-final.json` 记录实际组件哈希。后一次队列在测试结果累加时发生夹具字典冲突；这不是产品测试失败，原日志保留，缺少的 HTTP 项随后独立补跑。

插件实际源码的类型检查及 382 项测试、Chromium/Firefox 构建通过。Firefox 的真实可见浏览器另行完成接管所有权验收，不能用单元测试替代这条链路。

## Firefox 慢首字节与重载修复

服务器已发响应头但延迟 8 秒提供 body 时，Firefox 158.0 在约 8 秒后才发响应头事件；插件收到事件后约 0.16 秒完成 Native Messaging 提交。直接增加 Firefox blocking 权限没有改善这个延迟，实验及临时日志已撤回，没有保留该权限。

现在仅对**可信点击的同源 `download` 链接**，在浏览器发出真实 GET 请求头后提前提交确认。继续使用当前请求的标签页、请求头及 Cookie 边界，不伪造成功响应。普通导航及跨域 `download` 属性仍等待下载证据，后者不能用浏览器会忽略的属性作为接管依据。没有新增依赖或服务进程。

一次验收还发现重载后台后重复确认：原接管被拒绝，而延迟到达的 DownloadItem 又提交了一次 offer。现把浏览器 requestId 放入原有会话接管记录，重载后恢复同一决定；这份记录不保存请求头或凭据。仅凭相同 URL 不足以绑定另一个标签页。

`firefox-final.json` 使用生产 Firefox 插件、真实 Native Host/Core 与可见 Firefox，验证提前确认、接受后成品 SHA-256、等待浏览器原响应实际释放后再确认副本已清理、拒绝后完成、后台重载后拒绝恢复、桌面 403 后浏览器恢复、跨域不提前接管，以及每请求仅一条接管。明确同源链接的提示在约 0.45–0.52 秒内出现；跨域样本仍约 8.55 秒，不能宣称所有 Firefox 下载都消除了慢首字节等待。

Alt 绕过在隔离 Firefox profile 启用 `browser.altClickSave` 的条件下验证，文件在浏览器完成且无桌面接管。未启用该浏览器选项的前两轮没有发出请求，原始夹具失败记录保留；本项目没有更改用户浏览器偏好。

另有 `firefox-ui-final.json` 专门由代理实际点击“开始下载”“取消”，随后核对桌面成品与浏览器回退文件的 SHA-256；它与通过 Core API 驱动决策的批次分开记录，不冒充全部按钮、原生插件 popup 或真实网站验收。

## 失败记录与边界

早期 AB 对照因已有任务/文件重名，程序正常另存为 `_1` 后缀，夹具却等原文件名，误报超时。正式对照改为独立目录与唯一任务名称，原始失败报告保留。IDM 首次语言选择已由代理完成；包含初始化等待的早期样本不参与正式统计。

Firefox 探针的变量作用域、引号和重载后失效窗口也分别造成夹具失败，相关 JSON 保留，未抹掉或算作通过。`firefox-final.json` 的接受/拒绝经 Core API 驱动；实际确认按钮点击另见 `firefox-ui-final.json`。

## 复核与收尾

工作区基点为 `3e6574abe01dd63ff2a409e0221dabaf3b58bdde`，包含未提交修改；不是已经发布的版本。`source-hashes.json` 保存本轮修改文件，`binaries.json` 保存最终 bundle、Core 和测试程序哈希；Firefox 两份最终报告的后台 bundle 哈希与本地最终构建一致。环境见 `environment-final.json`。验证日志以 `.log.txt` 保存，避免被仓库的 `*.log` 忽略规则排除。

测试脚本中的 `C:\HLSRuntime`、`C:\QAWork` 和 `C:\HLSValidation` 均为沙盒客体路径；脚本依赖报告中的映射和构建产物，不能在宿主机直接执行。本证据目录保存脚本与记录，未复制竞品安装器及整套运行副本。

沙盒已关闭并销毁本轮客体数据，本轮误开的两个 OpenWith 进程已按 PID 与创建时间核对后关闭，先前已有的进程未动。项目仍为一个 `main` 分支、一个 worktree。本地生成目录的删除被自动审批以 `blocked by policy` 拒绝，没有具体原因，未换工具重试；因此安装器和运行副本目前仍留在 `.tool-cache/targeted-validation/idm-ab-20261019`（639 个文件、547,844,309 字节，约 522.5MiB），尚未达到只剩源码。旧构建缓存及插件依赖也仍存在，具体路径见总报告。
