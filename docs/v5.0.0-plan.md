# HLS Downloader 5.0.0 改造方案

版本号：**5.0.0**。这是大版本，壳换成常驻原生监督进程。  
工作分支：`cursor/native-shell-rewrite-5a2e`。安装包由 `v5.0.0` 标签构建。

一句话：**壳要像 IDM 一样常驻、小、快；能力要保住现在全部媒体/BT/接管；界面密度和分类参考 AB Download Manager；不准去抄 IDM 挂钩，也不准整仓 C++/Kotlin 重写引擎。**

---

## 1. 你要的，收成四条验收词

| 词 | 5.0.0 必须做到 | 明确不靠什么做到 |
| --- | --- | --- |
| **原生** | 托盘、确认窗、进度窗、完成窗、任务列表都是原生窗口，热路径没有 WebView2 | 不是 C++ 整仓重写，不是 Compose 复活 |
| **稳定** | 关主窗口继续下；崩溃可续；覆盖升级不丢任务；Range/HLS/BT 原有行为不回退 | 不是少功能换稳定 |
| **快** | 登录后进程已在；点下载只 Show 已建好的窗口；确认窗用管道里的文件名/链接/大小立刻上屏 | 不是把 Python 核心改成 C++ |
| **小** | 热路径去掉 3～4 个 WebView2；托盘进程本身很小；主列表按需打开 | 不是和 IDM 比总内存（Python+FFmpeg+libtorrent 还在） |
| **准** | 接管点用户要下的文件/媒体；播放器旁资源对得上；不抢图片、脚本、登录、OAuth | 不是 IDM 那种全机挂钩、见链就拦 |

笨重的根因是 **WebView2 × 多个窗口 + 点击还要等窗口启动**，不是 HLS 引擎「很傻」。5.0 改壳，不拆引擎。

## 2. 从三边各取什么

### 从 IDM 取（用法，不取挂钩）

- 开机/登录后托盘常驻，关列表 ≠ 退出。
- 确认窗、右下角进度小窗、完成置顶窗：**预先创建，隐藏，再显示**。
- 点击热路径：扩展暂停浏览器下载 → 立刻把 offer 交给已在的进程 → 窗口已有内容。
- 普通 HTTP：**Range 多连接，同一文件按偏移写入**（`payload.downloading` + `seek`）。这条 3.x 已经在用，5.0 保留并作为文件下载默认。
- 左侧是分类树：全部 / 未完成 / 已完成 / 压缩包、文档、音乐、视频、程序、常规。先做原生列表上的筛选，不阻塞第 1 期小窗。
- 动态分段（慢尾巴切开给空闲连接）：已有，保留。

**不取：** 浏览器捕获 DLL、网络监控 DLL、WFP/TDI、注入别的进程、系统代理中间人、见图片/脚本也接管。

### 从 AB Download Manager 取

- **原生界面**，不是套浏览器壳（ABDM 用 Compose；5.0 用 Rust 原生窗，避免再引入 JRE）。
- 扩展用 `webRequest` / `downloads.onCreated` 把真实下载交给本机，失败就放回浏览器。
- HTTP 任务：动态拆 part、校验长度/ETag/续传能力（你们已有同类实现）。
- 队列、分类目录、干净的设置页信息架构。
- 开源、本机、跨浏览器扩展；**不取**它偏窄的 HLS（只扫 m3u8），你们的播放器归属/MSE/直播比它准、比它全。

### 从现在的 HLS Downloader 全部保留

HTTP(S) Range、FTP/SFTP、HLS / LL-HLS、非 DRM DASH、直播检查点、BT/magnet、边下边播、投屏/TVBox、浏览器接管（点击意图、Cookie/重定向链、magnet、blob 所有权边界）、站点规则、限速/时段、镜像、完成音、病毒扫描、DPAPI、只监听 127.0.0.1、用户协议门、不绕过 DRM。

这些能力的代码继续在 **Python FastAPI 核心 + WXT 扩展**。5.0 换的是谁画窗口、谁先接到点击。

## 3. 5.0.0 过程模型

```
登录 / 安装后首次启动
        │
        ▼
 HLSDownloader.exe          ← 很小的常驻监督进程（Rust）
   托盘
   隐藏：确认窗 / 进度窗 / 完成窗   （启动时创建一次）
   需要时才：任务列表主窗
        │
        │ 命名管道（长度前缀 JSON，见 backend/app/native_shell.py）
        ▼
 python 核心                 ← 现有 FastAPI + 各协议 worker
   127.0.0.1 only
        ▲
 浏览器扩展 ── Native Messaging ──► 先到监督进程（热路径）
                                 再入队到核心（下载真正开始）
```

点击下载（目标延迟：监督进程已热时，确认窗 **几十毫秒内可见**）：

1. 扩展立刻暂停 `DownloadItem`。
2. Native Host 把 offer（文件名、URL、大小、类型）写进管道，**不必先等主窗口、不必先 GET 三份 HTTP**。
3. 监督进程把已存在的确认窗 Show + 置顶，用 snapshot 上屏。
4. 用户确定后，核心按现有逻辑建任务（HTTP 走 Range 拼文件；HLS 走清单分片）。
5. 进度/完成用另外两个已建好的小窗，不抢浏览器焦点（进度窗 `focusable=false` 的现有语义保留）。

关主窗口：只 `hide`。托盘还在，核心还在，直播还在录。

## 4. 技术选型（5.0 冻结）

| 层 | 5.0.0 | 禁止 |
| --- | --- | --- |
| 常驻壳 | Rust + 原生窗口（Win32 或 Slint）。一个进程、托盘、预创建 HWND | Electron、再加 WebView2 小窗、Kotlin/Compose、pywebview |
| 下载核心 | 现有 Python 3.12 + FastAPI + FFmpeg + libtorrent | 5.0 周期内用 C++/Kotlin 重写 HLS/BT |
| 浏览器 | 现有 WXT MV3；Native Host 改连监督进程 | DLL 注入、WFP |
| 本机 API | 核心仍提供 `127.0.0.1` HTTP；监督进程是第一个客户端 | 把核心改成可被网页直连 |
| 安装包 | NSIS + 便携包；启动监督进程，由它拉核心 | 先开一个 Chromium 主界面才算启动 |

C++ 完全重写 **不是** 5.0 方案。C++ 只允许出现在「某一个原生小窗」这种局部，且没有收益优于 Rust 时不必上。

## 5. 分期（每一期都要能跑、能测）

### 5.0.0-alpha（壳热路径）——用户开始觉得「不像网页了」

- 监督进程：托盘、单实例、开机可选启动。
- 三个预创建窗口：确认、进度、完成。
- 管道协议按 `NativeShellSupervisor`：`handoff` 带 snapshot，`presentable=true`。
- 扩展 offer 热路径改走监督进程；核心仍用现有 `/browser/handoffs` 落库。
- Tauri 主界面暂时可并存（开发开关），但 **点击接管不得依赖 Tauri 窗口已开**。
- 验收：核心已运行时，点一个普通文件下载，确认窗在无需新 WebView 的情况下弹出；拒绝后浏览器下载恢复（现有语义）。

### 5.0.0-beta（主列表也原生）

- 原生任务列表：全部 / 未完成 / 已完成 + 文件分类；搜索、暂停/开始/删除、打开目录。
- 设置、新建任务、日志仍接现有 API。
- 关列表 = 回托盘。
- 播放器、投屏 HUD：第一期可继续调核心的本机播放接口；若仍重，可后置，但 API 不能拆。

### 5.0.0（切安装包）

- 安装器/便携包带 `HLSNativeShell.exe`；启动后监督进程预创建确认/进度/完成窗。
- 主任务列表这一刀仍用现有桌面窗口（托盘 Open/Quit 也还在它上面），避免两个托盘图标。
- 升级：3.x → 5.0 保留 `%LOCALAPPDATA%\HLS Downloader`、任务库、下载目录、插件配对。
- 文档、版本号、扩展推荐版本一并升到 5.0.0。
- 回归：现有 HTTP Range smoke、HLS/LL-HLS/DASH、BT、接管、覆盖安装。

### 5.1 以后（可选，不挡 5.0）

- 队列空闲时核心休眠，再点下载再拉起（更小；直播/BT 进行中禁止休眠）。
- 分类树做成 IDM 那种左栏（在原生主窗上）。
- 播放器原生化。

## 6. 「准」的边界（5.0 写进验收，不许为了像 IDM 放松）

接管 **要**：用户点击的下载、`Content-Disposition: attachment`、路径/MIME 已是文件、magnet、已有 HTTP 身份的 blob。  
接管 **不要**：图片、脚本、样式、OAuth/登录页、无归属的动态页、无证据的 `blob:`、DRM/EME。

媒体按钮：按播放器证据归属（现有 MSE/fetch/currentSrc），不要做成 ABDM 那种整页扫一个 m3u8 就当成当前视频。

HTTP 拼接：继续 IDM 那种单文件 Range 写入；HLS/DASH 继续清单 + FFmpeg，禁止把 fMP4 当普通字节拼成 MP4。

---

## 7. 数量化验收（对「快 / 小」说实话）

在「监督进程已热、核心已听端口」的前提下：

- 点下载到确认窗可见：**P95 &lt; 100 ms**（本机 SSD、无杀毒首次扫描干扰）。
- 确认窗首帧：只用管道 snapshot，**0 次额外 HTTP** 才能出现文件名。
- 热路径 WebView2 进程数：**0**。
- 仅托盘空闲（无任务列表）：监督进程工作集目标 **远小于当前多 WebView 壳**（记录基线后再写死数字）。
- 总进程内存不必小于 IDM：核心 + FFmpeg + libtorrent 会在。

稳定：

- 关主窗 10 分钟直播仍在写分片。
- 杀监督进程后，核心按现有中断/恢复语义可续（或监督拉起核心）。
- 3.x 配置迁移到 5.0 不丢 token、任务、分类目录。

## 9. 明确不做（写进 5.0 范围，避免方案漂成 IDM 克隆）

1. C++ / Kotlin 整仓重写下载核心。  
2. 复制或仿制 IDM 捕获 DLL、WFP、TDI、注入。  
3. Electron。  
4. 为了「全接管」去抢图片、脚本、登录。  
5. 为了「小」删 HLS/直播/BT。  
6. 在 5.0 完成前停更 3.x 真实用户包。
