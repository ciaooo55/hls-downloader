# v7.0.3-r8 未签名预发布版

修复真实 QwenCloud 连续字幕预取在首个较长语音窗口完成时失败的问题。服务端会在音频仍在发送时创建响应，旧 Core 只记录提交窗口之后的响应，导致“字幕服务响应无法对应当前音频窗口”。现在从流式输入阶段保存响应身份，提交时保留，匹配的完成事件处理完毕后再清空；仍要求完成状态和响应身份同时匹配才推进字幕就绪范围。

仅更换安装包中的 Core；沿用 r7 的界面、播放器、插件和其他运行组件，不增加依赖或播放引擎。保留 r7 的 Firefox 单次 POST 接管和安装路径修复。所有交付未签名，本机不安装。

## 验收

字幕服务的 11 项定向回归在 Windows Sandbox 通过，覆盖提交前创建响应、连续第二个窗口、错误响应与未完成窗口不能就绪、停止、重连和凭据边界。生产 Core release 构建成功。

真实云端验收脚本 `scripts/smoke_qwencloud_continuous.py` 使用 [Wikimedia 公有领域的肯尼迪就职演讲录音](https://commons.wikimedia.org/wiki/File:JFK_inaugural_address.ogg)，截取前 96 秒并在沙盒网页播放。生产 Firefox 插件、Native Host、Core 和 FFmpeg 实际执行预取、识别、翻译和字幕显示；不上传用户视频。验收检查连续窗口、1.5 倍速、跳转到未翻译的第 72 秒、停止，以及任务、分片缓存和解码进程清理。具体执行结果以同版本 `VALIDATION.json` 为准。

上述云端验收已全部通过：9 个完成窗口覆盖开头 0–26.75 秒和跳转后的 72–84 秒，原文及中文译文实际显示；首次自动续播耗时约 19.2 秒。已验证的是这些窗口及控制流程，没有把整段 96 秒或 14 分钟原录音宣称为逐句质量验收通过。

修复后的生产 Core 另通过 21 项下载与边下边播回归：TS、fMP4、AES HLS、外置音轨、DASH、HTTP 的未完成跳转与同窗成品切换；完成、删除未完成任务、清理已完成任务后的缓存清理；暂停续传缓存和无关文件保留。播放器关闭后完成下载不会重新打开窗口。

最终 MSI 通过沙盒自选路径安装、系统 Downloads Known Folder 默认目录、真实 MDN 视频字节比对、插件 ZIP 与解包文件一致，以及卸载后产品注册清理。该项为 Core 专项，没有重跑未变化 UI。MSI 为 302,788,608 B，比 r7 小 4,096 B；安装目录为 675,446,538 B，比 r7 增加 2,224 B。闲置 Core 五秒样本约占整机 CPU 0.039%、RSS 17.6 MB，不能代表整个 UI 或所有硬件性能。

这项有限时长实测不能证明所有长视频的译文质量或永不等待。开始和跳转后仍需准备字幕；网络或云端处理跟不上时，播放器会暂停补齐。原用户网页仍受 Cloudflare/SmartScreen 限制，原媒体清单此前返回 403，不能标记为原片验收通过。投屏和 TVBox 真实设备仍按用户范围排除。
