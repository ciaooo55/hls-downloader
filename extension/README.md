# HLS Downloader 浏览器插件

版本：7.0.5。适用于 Firefox，以及 Chrome、Edge 等 Chromium 浏览器。插件通过 Native Messaging 连接 Windows 上的 HLS Downloader 桌面程序。

插件提供网页媒体识别、HLS/DASH 清晰度和音轨选择、普通下载接管、独立桌面确认、桌面离线回退、右键下载、选中链接批量发送，以及在线字幕的采集和控制。站点 Cookie 需要用户单独授权；在线字幕默认关闭，需要用户自行配置 QwenCloud 或百炼服务，见 [字幕配置](../docs/guides/qwencloud-subtitles.md)。

工具栏弹窗使用紧凑资源列表，高度随内容变化。每项直接提供下载和清晰度选择，复制链接、投屏与 TVBox 位于“更多”。字幕服务、API Key、全局开关、语言、同步模式、原文显示和默认偏移统一在主程序“设置 → 字幕翻译”中配置；插件只提供播放器选择、开始/停止和网页开关，并显示当前语言与模式。网页字幕的上一句、下一句和本页时间微调位于播放器上的“选项”，不修改主程序默认值。

Chrome/Edge 对明确的压缩包、安装包链接及同源 download 属性链接，在普通左键点击时交给主程序，阻止浏览器默认导航；Alt、Ctrl/Meta、Shift 点击和按大小过滤不采用该点击预接管。

Firefox 对用户明确点击的附件 GET 导航，在本次请求头可用、HTTP 请求尚未发出时交接，保留 Authorization、Referer、Origin 和 User-Agent。Cookie 仍需站点授权；获准导出的 Cookie 快照必须与本次请求一致，并复用于交接负载，否则保留浏览器传输。POST、XHR、已重定向或已收到响应的请求、已识别的非直连代理请求及需要按大小过滤的请求不走此提前接管路径。无明确附件点击、Alt 绕过、排除站点和普通预览仍保留原流程。

已经发出请求的普通文件和音视频文件在 Chromium/Firefox 中均由浏览器保全原响应，完成后交给桌面确认并导入任务，避免再次访问一次性地址。HLS/DASH 清单仍交给 Core 媒体引擎；Firefox 可在响应阶段完成这类清单的交接。没有隐藏浏览器下载栏，保全阶段会有浏览器下载记录，关闭浏览器也可能中断尚未完成的传输。PDF、图片和媒体的普通预览仍保留。

服务器明确标记为 `attachment` 的视频、音频和其他文件不依赖网页点击记录；脚本导航、GET 表单、新标签、重定向和直接打开下载地址也适用。POST/Blob 的处理方式见下文，不能据此宣称所有协议和入口均在浏览器下载前阻断。

主程序明确离线或拒绝接收时保留浏览器原下载；收到主程序持久接收回执后，由主程序负责确认、取消、重试和失败显示，不再等待首字节或自动恢复浏览器副本。发出交接后失联不能证明未接收，不会盲目重发浏览器导航。取消主程序确认表示取消本次下载。

Firefox 在响应阶段交接 HLS/DASH 时，先持久记录交接请求 ID；丢失回执时保留浏览器原响应，出现下载项后保全该项并按原 ID 查询桌面结果。只有查到持久接收回执才清理浏览器副本，结果未知时不另发一份交接。桌面已接收后发生的用户取消不会恢复浏览器下载。

Firefox 提前交接附件时，原 HTTP 请求尚未发出。此时丢失回执会停止原请求并提示错误；后续相同链接的点击通过已记录的业务 ID 查询结果，不另发一份下载。同一标签页、frame 和精确 URL 的并发导航共享正在进行的准备结果，读取 Cookie 期间也不会放行第二份请求。连续点击缺少新的点击记录、关闭接管或 Cookie 改变时，仍先查清已有交接，避免启动浏览器副本。桌面首次连接明确失败或明确拒绝接收时放行原请求，后续响应和下载项不再重复交接。

下载项接管也覆盖图片、JSON 和无扩展名文件。POST 下载和网页生成的 Blob/data 导出先由浏览器保存，再自动交给桌面确认并导入任务；任务完成后才删除浏览器副本，拒绝或失败保留原文件。POST 下载不会因自动接管而重复提交。

媒体响应、清单解析和缓存重放按来源页面隔离；切换 SPA 页面后，旧页面尚未完成的 fetch/XHR 和缓存观察不会变成新页面的媒体。仅变化 URL 片段（例如跳到评论区）仍视为同一页面。

fetch/XHR 的响应正文通过精确 URL 和可见响应字段关联到网络请求，防止同 URL 的并发请求借用另一份鉴权。无法确定唯一请求身份时不猜测凭据。网络媒体候选只接受 200、206 和缓存命中 304；错误、重定向、无正文响应，以及清单地址返回的 HTML 登录页、JSON 错误和图片不产生媒体入口，通用 XML 的 DASH 清单仍可识别。

播放器读取 ArrayBuffer、Blob、bytes 或二进制 XHR 中的 HLS/DASH 清单也可识别；检查复用网页已读取的数据，不改变网页收到的响应。站点播放器元数据也可从页面的 `response.json()` / `response.text()` 读取中提取清单，覆盖播放器预先保存原始 fetch 的情况。同一 HTTP 响应及其克隆共享正文解析结果，避免重复解析和上报；同 URL 的新响应仍独立处理，以更新签名链接。来源页面失效后不再上报旧结果。

媒体交接保留 Cookie 的作用域和有效期，以及 Authorization、自定义请求头、Referer、Origin、User-Agent 和代理上下文。已观察到的音视频、清单和密钥优先使用各自精确 URL 的请求身份，避免同目录或同路径不同查询参数的令牌互相覆盖；未观察到的分片使用目录上下文。候选请求上下文的收集上限保持为 32 个，并另行保留所选资源的身份。已有凭据缺失或不可解密时明确报错，需要重新获取凭据后重试。

后台清单解析也逐 URL 选择同一来源 frame 的请求身份，按目标路径读取已授权 Cookie；子清单不会继承另一 CDN 的 Cookie 或令牌。后台探测不跟随未观察的重定向，此时保留已识别的主清单信息，等待播放器提供目标请求；下载仍由 Core 处理。POST、无正文响应和扩展自身请求不触发后台重复探测，服务器明确拒绝后释放响应，不再立即换头重试。交接负载复用同一 Cookie 快照，并合并同时发生的桌面连接检查；持久接收回执仍是取消浏览器副本的唯一依据。

浏览器投屏/TVBox 推送在桌面选择设备后，由 Core 代理媒体请求，保留网页的 Cookie、Authorization、防盗链请求头和代理设置。设备拿到随机局域网播放地址；HLS/DASH 子清单、音轨、密钥及分片也经过同一代理，媒体按块转发。LL-HLS 的阻塞重载和增量清单参数经校验后传给上游，并继续使用原始清单的精确请求凭据。此链路需要同步更新桌面端、Core 和 Native Host。非 GET 媒体应先下载后投屏；外部 XML 引用的 MPD、未解析的 HLS 变量和 DRM 解密暂不支持，验证范围见[参考机制与本地验证记录](../docs/validation/browser-reference-completion.md)。

## 开发与审核

[审核构建说明](AMO-BUILD.md) 包含工具版本、锁定依赖构建命令、权限说明和服务依赖。[插件隐私说明](PRIVACY.md) 描述数据传输和用户控制。

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm run package:store
pnpm exec web-ext lint --source-dir .output/firefox-mv3
```

`package:store` 生成 Chromium 插件 ZIP、Firefox 未签名 ZIP 和 Firefox 审核源码 ZIP。打包不调用签名服务、不上传文件。Firefox 的 Gecko ID 和 Chromium 公钥保持既有商店身份。

## 本地加载

先安装并启动 HLS Downloader 桌面程序。Firefox 在 `about:debugging#/runtime/this-firefox` 使用“临时载入附加组件”，选择 `.output/firefox-mv3/manifest.json`。Chrome 或 Edge 在扩展管理页启用开发者模式，加载 `.output/chrome-mv3` 目录。

交给签名服务的是 Firefox 插件 ZIP；审核需要源码时，同时提交源码 ZIP。签名后的 XPI 由用户安装。临时加载用于功能验证。
